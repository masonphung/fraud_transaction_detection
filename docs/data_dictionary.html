Fraud Detection Data Dictionary — raw transaction schema and feature-enriched schema

Table 1 — Raw transaction schema

producer src/producer/main.py
field type range / format description
transaction_id string UUID v4 Unique identifier for each transaction. Generated via fake.uuid4(). Used as the Kafka message key.
user_id integer 1000 – 9999 Simulated cardholder identifier. 50 values are pre-selected as compromised users to seed account-takeover fraud patterns.
amount float 0.01 – 10,000.00 Transaction value in AUD, rounded to 2 decimal places. Fraud patterns skew the distribution: account-takeover transactions are inflated to $500–$5,000; card-testing transactions are capped at $2.
currency string ISO 4217 (3-char) Transaction currency code. Fixed to AUD for all generated records in the current implementation.
merchant string free text Merchant name. Normally drawn from fake.company(). Fraud patterns replace this with a high-risk merchant name (QuickCash, GlobalDigital, FastMoneyX) for account-takeover cases.
timestamp datetime ISO 8601 UTC ±5 min Event time of the transaction. Jittered by ±300 seconds from datetime.now(UTC) to simulate natural clock drift between systems.
location string ISO 3166-1 alpha-2 2-letter country code of the transaction. Geo-anomaly fraud cases override this with a high-risk country: RU, CN, NG, or GB. Card-testing cases are pinned to US.
is_fraud binary 0 or 1 Ground-truth fraud label. 1 = fraudulent, 0 = legitimate. Simulated prevalence is 1–2%, consistent with industry-observed rates. Applied via four weighted fraud patterns plus a 0.2% baseline random fraud rate.

Table 2 — Feature-enriched training schema

training DAG src/dags/fraud_detection_training.py · create_features()
field type group range / formula description
amount float raw 0.01 – 10,000 Carried forward unchanged from the raw schema. Primary monetary signal for the model.
transaction_hour integer temporal 0 – 23 Hour of day extracted from timestamp (UTC). Used as a cyclical proxy for time-of-day risk.
day_of_week integer temporal 0 (Mon) – 6 (Sun) ISO day-of-week from timestamp.dt.dayofweek. Also used to derive is_weekend.
transaction_day integer temporal 1 – 31 Calendar day of month from timestamp.dt.day. Captures end-of-month spending spikes common in billing fraud.
transaction_month integer temporal 1 – 12 Month of year from timestamp.dt.month. Captures seasonal fraud seasonality (e.g. holiday periods).
is_night binary temporal hour ≥ 22 or < 5 → 1 Flags transactions occurring between 10 PM and 5 AM UTC. Night-time activity is a significant fraud risk signal.
is_weekend binary temporal day_of_week ∈ {5,6} → 1 Flags Saturday and Sunday transactions. Reduced monitoring hours on weekends can elevate fraud risk.
transaction_count_last_24h float behavioural rolling count ≥ 0 Number of prior transactions by the same user_id within the preceding 24-hour window (closed='left', excludes current row). Detects velocity spikes typical of card-testing attacks.
time_since_last_transaction float behavioural seconds ≥ 0 (0 = first txn) Seconds elapsed since the user's previous transaction, computed via groupby(user_id).diff(). Very short intervals are a card-testing indicator; 0 for the user's first transaction.
transaction_count_last_7d float behavioural rolling count ≥ 0 Number of prior transactions by the same user_id in the preceding 7-day window. Provides a medium-term velocity baseline to complement the 24-hour count.
amount_to_avg_ratio float monetary ≥ 0 (default 1.0) Current transaction amount divided by the user's rolling 14-day mean amount (min_periods=1). Values significantly above 1 flag abnormally large transactions relative to the user's own history. Defaults to 1.0 when no prior transactions exist.
is_high_risk_merchant binary merchant merchant ∈ config list → 1 Flags transactions at merchants listed in config.yaml → high_risk_merchants. Defaults to ['QuickCash', 'GlobalDigital', 'FastMoneyX']. OrdinalEncoder is applied in the preprocessing step of the ImbPipeline.
is_fraud binary label 0 or 1 Target variable. Retained from the raw schema; separated as y before training. SMOTE oversampling is applied inside the pipeline on the training split only to preserve true class distribution in the test set.

All 12 features above (excluding is_fraud) are passed to the XGBoost classifier. Raw fields not listed here (transaction_id, user_id, timestamp, currency, merchant, location) are dropped before model input.
